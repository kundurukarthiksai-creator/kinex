# Kinex: what to say to the judges

## Your main message

**Kinex makes 3D exploration easier: describe a model, then explore and change it with your hands using an ordinary webcam.**

Lead with an educational example, then demonstrate it. You do not need to name every library before the judge understands what the product does.

## A 30-second introduction to practise

“Kinex is a browser-based 3D learning workspace. You describe what you want using text or voice, and then move, rotate and resize models with your hands through a normal webcam. A student can explore a ship’s hull and passenger decks, change individual colors, and inspect its structure without learning complicated modeling controls or buying a VR headset. We combine AI scene creation, real-time 3D graphics and local hand tracking, with offline models and common edits available when the AI connection fails.”

## A shorter answer if a judge interrupts

“Think of Kinex as a 3D learning table controlled by words and your hands. Our current example is marine design: create a ship, turn it, examine its structure, and change its colors.”

## Show these four things in 90 seconds

| Time | Do | Explain |
| --- | --- | --- |
| 0–15 seconds | Type “Create a realistic ship.” | “This detailed ship is an original Kinex model loaded locally, so it is available reliably.” |
| 15–40 seconds | Type or say “Create a detailed lighthouse with a red roof, white tower and yellow lamp.” | “This custom description uses the AI to construct editable geometry.” |
| 40–65 seconds | Select the ship under More options → Objects. Inspect it, enable hand controls, pinch and turn it. | “MediaPipe tracks my hand on this device. A pinch becomes a virtual grab or rotation.” |
| 65–90 seconds | Say “Make the hull blue and windows yellow.” Undo a change. Open Edit and show wireframe. | “Students can explore the structure and compare parts. Our lesson connects the hull’s shape to displacement and buoyancy; this scene illustrates those ideas rather than simulating water.” |

For two-hand scaling and twisting, return to World, choose Move, grab the ship with one pinch and add a second pinch. In Inspect, two hands zoom and roll the view.

If voice is unavailable, type. If hand tracking struggles with the venue lighting, use the mouse. If custom AI fails, the local lighthouse recipe can still show the interaction. Say which path is being used.

## Likely questions and answers

### 1. What problem are you solving?

“3D concepts can be difficult to understand from flat pictures, while full modeling tools take time to learn. We are testing a simpler way to create and explore spatial models with familiar language and hand movements.”

### 2. Who would use it?

“Our first intended users are students, teachers and people exploring basic product or spatial ideas. We are focusing the demo on an educational workflow so the interaction has a clear purpose.”

These are intended users. Do not claim classroom adoption, measured learning improvements or customer demand without evidence.

### 3. Give me one real-world use case.

“A teacher introduces marine design. Students turn a ship, identify the hull, decks and lifeboats, and discuss why the submerged hull displaces water. The same interaction could support other appropriate models, but our current prepared lesson is marine design.”

### 4. Does the AI generate that realistic ship from scratch?

“No. The detailed ship is an original model built from Three.js geometry and selected by the text request. Other supported detailed subjects use credited local assets. Novel requests, such as the lighthouse description, use Gemini to compose editable shapes. We show these as different model sources.”

This distinction matters. Do not say every detailed object is freshly generated by AI.

### 5. Can it make any photorealistic object?

“Not yet. Our chat model creates bounded shape approximations. The detailed library and imported GLB models provide richer geometry and textures. Novel photorealistic text-to-3D would require a dedicated mesh-generation service.”

An optional image-to-mesh integration exists in the code but requires a separately configured provider. Do not present an unconfigured service as a working live feature.

### 6. Is this ray reconstruction, NeRF, Gaussian splatting or ray tracing?

“No. Our current app uses WebGL rendering with Three.js, plus meshes and AI-assisted shape construction. A photo produces an approximation, not a recovered scene with accurate unseen surfaces. Those reconstruction methods would be separate future work.”

### 7. How does the system work?

“Text or browser speech recognition produces a command. Common commands run locally; custom descriptions go through our server proxy to Gemini, which returns structured scene instructions. We validate and bound those instructions, render objects with Three.js, and use MediaPipe landmarks to interpret hand movements. Rapier handles object physics.”

A useful sequence to remember is: **words → scene instructions → 3D model; webcam → landmarks → interaction**.

### 8. Which parts actually use AI?

“Gemini handles new scene descriptions, some complex changes and photo interpretation. MediaPipe is a pretrained hand-tracking model. Simple color, size, rotation, undo and library commands use deterministic local code for speed and reliability. We did not train either model.”

### 9. What is the technology stack?

“React and JavaScript with Vite for the application; Three.js through React Three Fiber for graphics; Rapier for physics; MediaPipe for hands; Gemini through an API-compatible server proxy for custom scene instructions. Voice transcription uses the browser’s speech-recognition API.”

The proposal mentioned vanilla JavaScript; this implementation uses React. Speech transcription is not performed by Gemini in the current app.

### 10. How do you recognize gestures?

“MediaPipe returns 21 landmarks per hand. We smooth their movement, compare finger distances relative to the hand’s size, and use different pinch start/release thresholds to reduce flicker. We match hands across frames, map a virtual cursor to the canvas, and use raycasting to select or manipulate an object.”

A pinch controls grabbing or rotation. Two hands use their relative separation and angle for scaling and turning. Camera distance, lighting and occlusion still affect reliability.

### 11. How is it different from a normal 3D viewer or chatbot?

“The contribution is the working interaction loop: language creates or changes the scene, hands manipulate it, and the screen gives immediate feedback. A chatbot normally returns text; a conventional viewer usually relies on mouse controls. Our prototype brings these together around a teaching example.”

Do not claim that no other product combines these technologies, or that the idea is guaranteed to win.

### 12. Why not use a mouse or buy a VR headset?

“Mouse controls remain useful and are supported. Hand interaction offers another way to explore spatial objects using equipment people may already have. Kinex does not need a headset; it also does not provide stereoscopic immersion or precise six-degree-of-freedom VR tracking.”

### 13. How fast is it?

“Local edits do not wait for an AI round trip. Observed request times varied with model complexity and server conditions; custom creation should not be promised to complete in a fixed number of seconds. Text requests have an 18-second total budget; photo and refinement requests have a 35-second budget. Cancellation and local fallbacks keep the workspace usable.”

These are observations and limits, not guaranteed response times. The renderer and hand inference run at different rates; we cap hand inference at 24 fps and display its measured rate in Tracking details.

### 14. Why does hand tracking run in a worker?

“Inference can block the browser’s main thread. We move it into a background worker when supported, use smaller inference frames and limit the inference rate. The UI and 3D renderer have more opportunity to stay responsive. A compatibility fallback is available.”

### 15. What happens if the internet or AI server stops working?

“Once the local application and its assets are available, the bundled ship and library, common edits, undo/redo and local hand tracking can continue. Custom AI creation and photo interpretation need their provider. Browser speech recognition may also need an online service. We do not claim a fresh offline visit works without an application server or cached assets.”

### 16. Is webcam video uploaded? Where are API keys and project data stored?

“Hand tracking runs on the device. For photo reconstruction, the user previews a still and explicitly chooses to send it to the AI. The browser’s speech service may process microphone audio separately. Projects and imported model blobs are stored in IndexedDB in that browser; reference photos are excluded from automatic saves. The provider key stays in the server’s ignored environment file and is added by the proxy.”

The current prototype is a local development/preview application. A public deployment needs a properly protected backend; a plain static upload does not provide its credential proxy.

### 17. How reliable is it, and what did you test?

“We have 83 automated tests covering scene logic, gestures, history, persistence, parsing, voice lifecycle and material edits. Browser checks exercise the actual workflows, exports, reloads, worker startup and simulated AI outages. Controlled landmark tests verify rotation and two-hand interactions. We still need live testing on the presentation laptop and in venue lighting.”

Do not describe mocked speech events as proof of real speech accuracy, or automated camera input as a physical usability study. Update the numbers if tests change.

### 18. How is this accessible?

“Ordinary browser hardware and alternative input methods can reduce some barriers. Text, mouse and keyboard remain available if voice or gestures are unsuitable. We have not completed an accessibility audit or user study, and hand gestures will not suit everyone.”

### 19. What are the main limitations and next steps?

“Webcam depth and occlusion are limited, browser voice support varies, and arbitrary AI-generated geometry is approximate. Next we would prioritize calibration and user testing, a carefully chosen educational model set, and a dedicated text-to-3D provider if realistic new meshes are required. We want one reliable learning workflow before expanding scope.”

### 20. What did your team build, and did you start from an existing project?

“We started from an existing Kinex prototype and developed improvements in our own fork: the simplified interface, detailed ship and material controls, gesture reliability work, transactional history, offline behavior and the educational demo. We can show the commits and explain our changes.”

Describe the existing project and team contributions accurately. If asked about AI-assisted development, say which coding tools you used and explain the decisions you understand. Do not claim inherited code, externally supplied assets, or AI-generated code was entirely hand-authored. Hackathon eligibility and disclosure should follow the event’s actual rules; this guide does not verify those rules.

### 21. What does it cost, and could it scale?

“The browser handles rendering and hand tracking; the AI provider meters custom requests. We reduce calls with local commands and cached creation plans. We have not run a production cost or load study, so we do not quote a fixed cost per user. A public service would need authenticated requests, rate limits, quotas and a suitable backend.”

### 22. How will you prove it is useful?

“We would test one specific task with students or teachers—for example identifying ship components and explaining their relationship—then compare completion, errors and understanding with a conventional viewer. We do not yet have evidence that gestures improve learning; that is something we need to measure.”

## Five things to remember before you present

1. Start with the user and the task, not a list of technologies.
2. Explain what the judge is about to see, then show it.
3. Distinguish the detailed local ship from custom AI shape generation.
4. If you do not know an answer, say what you know and what you would test next.
5. Keep the claim small and credible: **an accessible prototype for exploring 3D educational models with words and hands**.
